# MemFS 最佳实践指南

> MemFS 是知识卡片网络的数字化系统。本文档指导你如何有效地组织和管理知识。

---

## 一、核心理念：知识卡片网络

### 1.1 什么是知识卡片

**知识卡片**是对一个独立概念的完整记录，包含：

| 字段 | 说明 | 示例 |
|-----|------|-----|
| **name** | 概念的标准化名称 | "涂尔干", "功能主义", "《社会分工论》" |
| **entityType** | 偏正结构类型 | `知识/人物`, `知识/理论`, `图谱/事件`, `工具/框架` |
| **definition** | **启发性定义**：揭示本质 + 关联线索，引导下一步检索 | "社会团结的两种类型：机械团结（相似性凝聚）vs 有机团结（分工协作），对应涂尔干社会学年《社会分工论》" |
| **definitionSource** | 定义来源 | `https://en.wikipedia.org/wiki/Emile_Durkheim`, `《社会分工论》`, `涂尔干在《社会分工论》中提出` |
| **observations** | 补充信息 | 阅读笔记、背景资料、争议点、引用 |

### 1.2 知识卡片 vs 日常笔记

| 日常笔记 | 知识卡片 |
|---------|---------|
| "今天读了涂尔干" | 涂尔干的社会团结理论 |
| "功能主义和符号互动论不一样" | 功能主义：社会整体优先于部分 |
| "这篇文章说得有道理" | Beck 的个体化理论 |
| 随想、感想、心情 | 可验证的知识点 |

**MemFS 只存储知识卡片，不存储闲聊内容。**

## 二、实体命名规范

### 2.1 命名原则

```
✅ 正确示例：
- "涂尔干" (知识/人物)
- "功能主义" (知识/理论)
- "《社会分工论》" (知识/文献)
- "社会团结" (知识/概念)
- "19世纪法国社会学" (图谱/时期)
- "社会学年" (图谱/事件)

❌ 错误示例：
- "涂尔干这个人" (冗余描述)
- "关于功能主义的想法" (主观感受)
- "今天读的书" (时间绑定)
- "重要概念" (模糊不清)
```

## 二.2 Definition 启发性原则

### 2.2.1 什么是启发性定义

**启发性定义** = **本质揭示** + **关联线索**

- **本质揭示**：说明"是什么"的核心特征
- **关联线索**：指出"通向哪里"的相关概念

### 2.2.2 启发性 vs 描述性

| 描述性定义 | 启发性定义 |
|-----------|-----------|
| "涂尔干是法国社会学家" | "涂尔干：社会学奠基人，与韦伯、马克思并称社会学三大家，功能主义开创者，著有《社会分工论》《自杀论》" |
| "功能主义是一种理论" | "功能主义：社会整体先于部分并决定部分的社会学理论流派，涂尔干开创，帕森斯发展，默顿提出中距理论" |
| "《自杀论》是涂尔干的书" | "《自杀论》：涂尔干1897年著作，运用社会统计学方法研究社会失范问题，奠定实证主义社会学方法论基础" |

### 2.2.3 启发性要素

好的 definition 应包含：

1. **核心特征**：用一句话点明本质
2. **关键关联**：指出主要相关人物/理论/作品
3. **时间/学派位置**：帮助定位在知识图谱中的位置

### 2.2.4 模板

```
{核心定义}，{关联人物/理论}，{代表作品/核心命题}
```

**示例：**
```javascript
{
  name: "社会团结",
  entityType: "知识/概念",
  definition: "社会团结：社会成员基于凝聚力的结合状态，涂尔干在《社会分工论》中区分机械团结（相似性）与有机团结（差异性互补），是理解社会整合与社会变迁的核心概念"
}

{
  name: "失范",
  entityType: "知识/概念", 
  definition: "失范：涂尔干在《自杀论》中提出，指社会规范瓦解导致个体无所适从的状态，现代化进程中传统约束力减弱而新规范尚未建立，常用来解释自杀、社会解组等现象"
}
```

### 2.2.5 自检问题

写完 definition 后问自己：
- [ ] 读了这个定义，我知道它**是什么**吗？
- [ ] 读了这个定义，我知道**下一步该查谁/查什么**吗？
- [ ] 读了这个定义，我能**联想到相关概念**吗？

### 2.2 实体类型：偏正结构体系

偏正结构 = [修饰语]/[中心语]，可嵌套多组修饰语，体现层级与关联。

#### 2.2.1 一级类型（顶层分类）

| 顶层类型 | 说明 | 示例 |
|---------|------|------|
| `知识` | 认知性内容 | 人物、理论、概念、文献 |
| `图谱` | 关联性内容 | 事件、学派、流派、时期 |
| `工具` | 方法性内容 | 框架、方法、模型、技术 |

#### 2.2.2 二级类型（知识/图谱/工具的子类）

**知识/ 体系**

| entityType | 说明 | 命名特点 |
|------------|------|---------|
| `知识/人物` | 人物主体 | 人名 |
| `知识/理论` | 理论、学说 | 理论名 |
| `知识/概念` | 抽象术语 | 概念名 |
| `知识/文献` | 作品、文献 | 《书名》 |
| `知识/命题` | 判断、论点 | 人名+在+作品+提出 |

**图谱/ 体系**

| entityType | 说明 | 命名特点 |
|------------|------|---------|
| `图谱/事件` | 时间性事件 | 时间+地点+事件 |
| `图谱/学派` | 学术流派 | 时代+领域+派别 |
| `图谱/时期` | 历史时期 | 时代+领域 |
| `图谱/地域` | 地理区域 | 地区/机构 |

**工具/ 体系**

| entityType | 说明 | 命名特点 |
|------------|------|---------|
| `工具/框架` | 分析框架 | 框架名 |
| `工具/方法` | 研究方法 | 方法名 |
| `工具/模型` | 理论模型 | 模型名 |
| `工具/技术` | 具体技术 | 技术名 |

#### 2.2.3 嵌套示例（体现关联性）

通过 entityType 体现实体间关系：

```javascript
// 人物提出的理论
{
  name: "涂尔干",
  entityType: "知识/人物",
  relation: { to: "社会团结理论", relationType: "开创" }
}

// 人物参与的事件
{
  name: "社会学学年",
  entityType: "图谱/事件",
  relation: { to: "涂尔干", relationType: "参与" }
}

// 理论间的关联
{
  name: "功能主义",
  entityType: "知识/理论",
  relation: { to: "社会团结理论", relationType: "包含" }
}
```

#### 2.2.4 类型对照表

| 旧版 entityType | 新版偏正结构 |
|----------------|-------------|
| `person` | `知识/人物` |
| `theory` | `知识/理论` |
| `concept` | `知识/概念` |
| `document` | `知识/文献` |
| `event` | `图谱/事件` |
| `school` | `图谱/学派` |
| `region` | `图谱/地域` |

## 三、观察（Observation）使用指南

### 3.1 观察的本质

**观察**是实体的补充信息，存储在独立的 inode 表中：

```jsonl
{"type":"entity","name":"涂尔干","entityType":"知识/人物","observationIds":[1,2]}
{"type":"observation","id":1,"content":"《社会分工论》作者","createdAt":{"utc":"..."}}
{"type":"observation","id":2,"content":"提出机械团结与有机团结","createdAt":{"utc":"..."}}
```

### 3.2 好的观察 vs 差的观察

**好的观察：**
```javascript
{
  "content": "机械团结：在前工业社会，基于相似性（信仰、习俗相同）形成的社会凝聚力"
}
{
  "content": "有机团结：在工业社会，基于差异性（分工合作）形成的社会凝聚力"
}
```

**差的观察：**
```javascript
// ❌ 描述过于笼统
{ "content": "很重要" }

// ❌ 包含个人情绪
{ "content": "我觉得这个理论很有道理" }

// ❌ 时间绑定
{ "content": "2024年3月读到这里" }

// ❌ 重复定义
{ "content": "涂尔干是社会学家" }
```

### 3.3 观察复用（硬链接）

**相同观察可被多个实体共享：**

```javascript
// 创建两个实体，共享同一观察
await createEntity([
  { name: "涂尔干", observations: ["法国社会学家"] },
  { name: "韦伯", observations: ["法国社会学家"] }  // 自动复用
]);

// 底层：observation id=1 被两个实体引用
{
  "entities": [
    { "name": "涂尔干", "observationIds": [1] },
    { "name": "韦伯", "observationIds": [1] }
  ],
  "observations": [
    { "id": 1, "content": "法国社会学家" }
  ]
}
```

### 3.4 Copy-on-Write 机制

当修改共享观察时，系统自动创建新副本：

```javascript
// 修改涂尔干的共享观察
await updateNode({
  entityName: "涂尔干",
  observationUpdates: [
    { oldContent: "法国社会学家", newContent: "法国社会学家，社会学奠基人" }
  ]
});

// 结果：涂尔干获得新观察，韦伯保持不变
{
  "observations": [
    { "id": 1, "content": "法国社会学家" },           // 韦伯使用
    { "id": 5, "content": "法国社会学家，社会学奠基人" } // 涂尔干新观察
  ]
}
```

## 四、关系（Relation）建立指南

### 4.1 关系类型参考

| relationType | 适用场景 | 示例 |
|--------------|---------|------|
| `开创` | 理论/学派的创立者 | 涂尔干 → 功能主义 (开创) |
| `发展` | 后续学者对理论的推进 | 帕森斯 → 功能主义 (发展) |
| `影响` | 思想上的启发关系 | 涂尔干 → 毛泽东 (影响) |
| `对立` | 理论上的反对关系 | 功能主义 ↔ 冲突论 (对立) |
| `对比` | 并列比较 | 涂尔干 ↔ 韦伯 (对比) |
| `引用` | 文献引用关系 | 《新教伦理》 → 《社会分工论》 (引用) |
| `同时` | 同一时期的学者 | 涂尔干 ↔ 韦伯 (同时) |
| `师生` | 教育/指导关系 | 涂尔干 → 莫斯 (师生) |
| `继承` | 学派传承 | 帕森斯 → 默顿 (继承) |

### 4.2 关系建立时机

**建立关系 when：**
- 发现两个概念之间的逻辑联系
- 读到引用了其他学者的理论
- 理解了一个理论对另一个的影响
- 对比两个相似/对立的理论

**不建立关系 when：**
- 仅知道两个概念都存在
- 没有明确的逻辑关联
- 关系过于模糊（"可能有关"）

## 五、搜索（searchNode）使用技巧

### 5.1 混合搜索 vs 关键词搜索

```javascript
// 混合搜索（默认）：BM25 + 模糊匹配
await searchNode("功能主义");

// 关键词搜索：精确匹配
await searchNode("功能主义", { legacyGrep: true });
```

### 5.2 搜索参数调优

```javascript
await searchNode("涂尔干", {
  limit: 10,           // 返回数量
  bm25Weight: 0.7,     // BM25 权重
  fuzzyWeight: 0.3,    // 模糊匹配权重
  minScore: 0.1        // 最低相关性阈值
});
```

### 5.3 提高搜索精度

1. **使用标准化名称**：搜索"涂尔干"而非"杜尔干"
2. **使用全称**：搜索"《社会分工论》"而非"分工论"
3. **添加相关术语**：多词搜索提高精度

## 六、工作流程建议

### 6.1 日常积累

```
阅读文献 → 提取知识点 → 创建/更新实体 → 建立关联
```

**步骤 1：阅读并提取**
- 识别核心概念和关键论述
- 记录定义来源

**步骤 2：卡片化**
```javascript
await createEntity([{
  name: "个体化理论",
  entityType: "知识/理论",
  definition: "个体化理论：Beck 在《风险社会》中提出，指现代社会从标准化个体向自主建构人生叙事的个体转变，阶级、家庭、性别等传统约束力弱化但个体风险增加，与功能主义形成张力",
  definitionSource: "https://en.wikipedia.org/wiki/Ulrich_Beck",
  observations: [
    "个体必须自主建构人生叙事",
    "传统阶级、家庭、性别角色弱化"
  ]
}]);
```

**步骤 3：建立关联**
```javascript
await createRelation([
  { from: "个体化理论", to: "Beck", relationType: "开创" },
  { from: "个体化理论", to: "风险社会", relationType: "基于" },
  { from: "个体化理论", to: "功能主义", relationType: "对立" }
]);
```

### 6.2 定期整理

**每周一次：**
- `listNode()` 查看新增实体
- `getOrphanObservation()` 检查孤儿观察
- 清理无用数据

**每月一次：**
- `searchNode()` 检索核心概念，确保知识网络完整
- 补充缺失的关系
- 更新过时的定义

### 6.3 写作辅助

**查找主题相关知识：**
```javascript
const results = await searchNode("现代化理论");
for (const entity of results.entities) {
  const detail = await readNode([entity.name]);
  // 使用详情
}
```

## 八、常见问题

### Q1: 实体名称重复怎么办？

MemFS 会检查同名实体，如果存在则跳过创建。可用 `searchNode()` 先搜索。

### Q2: 如何处理模糊概念？

使用 `知识/概念` 类型，通过 definition 和 observations 明确边界：
```javascript
{
  name: "现代性",
  entityType: "知识/概念",
  definition: "现代性：社会从传统向现代转变过程中形成的特征体系，韦伯以理性化为核心，涂尔干关注社会分工，马克思聚焦资本主义生产方式，Beck 提出第二现代性，是理解西方社会转型的核心框架",
  definitionSource: "韦伯在《经济与社会》中提出",
  observations: [
    "理性化：韦伯核心议题",
    "工业化：Marx 分析对象",
    "个体化：Beck 现代性论述"
  ]
}
```

### Q3: 观察太多会混乱？

- 每个观察一个知识点
- 避免冗余信息
- 定期用 `getOrphanObservation()` 检查孤儿

### Q4: 关系类型不确定？

选择最精确的 relationType。如果确实模糊，可用 `相关` 作为保守选择。

### Q5: definitionSource 有哪些格式？

**优先顺序：URL > 作品名 > 提出格式**

```javascript
// 1. URL（最优先）
definitionSource: "https://en.wikipedia.org/wiki/Emile_Durkheim"
definitionSource: "https://plato.stanford.edu/entries/functionalism/"

// 2. 作品名（中文加书名号）
definitionSource: "《社会分工论》"
definitionSource: "《资本论》第一卷

// 3. 提出格式（适用于命题、定理、理论）
definitionSource: "涂尔干在《社会分工论》中提出"
definitionSource: "韦伯在《经济与社会》中系统阐述"
definitionSource: "马克思在《共产党宣言》中宣告"
```

**格式规则：**
- URL：完整可访问的链接
- 作品名：中文加《》，外文加斜体或引号
- 提出格式：`主体 + 在 + 作品/地点 + 提出/阐述/宣告`

## 九、行为准则

**MemFS 只存储：**
- 可验证的事实
- 标准化的概念定义
- 明确的理论关联
- 有来源的论述

**MemFS 不存储：**
- 个人感想和情绪
- 时间绑定的临时笔记
- 模糊的"可能有关"
- 重复的已有信息
